## AI-DLCとは

**AI-Driven Development Life Cycle（AI-DLC）** は、ソフトウェア開発にAIを中心的なパートナーとして組み込む方法論です。

AWSが提唱するこのアプローチは、「AIが単にコードを提案するツール」でも「完全に自律して動くシステム」でもなく、**AIと人間が動的なチームとして協働する**開発パラダイムです。

### コアコンセプト

> 「AI が実行し、人間が監視する」

AIが詳細な作業計画を提案し、意図の確認を繰り返しながら進行します。最終決定は常に人間に委ねられます。

---

## 従来手法との比較

| 手法 | 説明 | AI-DLCとの違い |
|------|------|----------------|
| **AI支援型開発** | 特定のタスク（コード補完・説明等）のみをAIで強化 | AI-DLCはライフサイクル全体を通じてAIが構造化協力 |
| **自律型AI開発** | AIが完全自動でコードを生成・デプロイ | AI-DLCは各フェーズで人間の承認ゲートを設置 |
| **AI-DLC** | AIがルーティンを担い、人間が戦略・判断を担う | 速度と品質制御の両立 |

---

## 3つの開発フェーズ

AI-DLCは3フェーズで構成されます。ワークフローはプロジェクトの複雑さに応じて**自動的に適応**します。

```
🔵 INCEPTION（計画）  →  🟢 CONSTRUCTION（実装）  →  🟡 OPERATIONS（運用）
   WHAT & WHY を決める        HOW を決めて作る          デプロイ・監視（今後）
```

### 🔵 Inception フェーズ
- ビジネス意図を詳細な要件・ユーザーストーリーに変換
- アーキテクチャ・コンポーネント設計
- 並行開発のための「作業単位（Units of Work）」分解
- **条件付きステージを含む**：既存コードベースのリバースエンジニアリングなど

### 🟢 Construction フェーズ
- 作業単位ごとの詳細設計（機能設計・NFR設計・インフラ設計）
- コード生成：計画承認 → 生成の2段階
- ビルド・テスト指示の自動生成

### 🟡 Operations フェーズ
- **現在は将来拡張のプレースホルダー**
- IaC管理、デプロイ、監視、インシデント対応を予定

---

## 主要な特徴

| 特徴 | 説明 |
|------|------|
| **適応的インテリジェンス** | 複雑さに応じてステージの深さを自動調整。単純なバグ修正はコード生成に直行 |
| **コンテキスト対応** | 既存コードベースの有無（brownfield＝既存あり／greenfield＝新規）を検出して対応 |
| **リスクベース** | 複雑な変更は包括的な処理、シンプルな変更は効率的な処理 |
| **質問駆動** | 構造化された選択式の質問をファイルに記録。チャットでのインライン質問なし |
| **常に人間が制御** | 各フェーズの実行計画を確認し、承認してから進む |
| **拡張可能** | セキュリティ・コンプライアンス・組織固有ルールを追加できる拡張システム |

## 主なメリット

### 開発速度
数週間かかるタスクが数時間〜数日で完了。AIが計画・実装・テスト生成を一貫して担うため。

### イノベーション
定型業務が減り、チームは問題解決・創造的思考に集中できる。

### 品質向上
各フェーズで継続的に意図を確認するため、実装が正確で一貫している。組織標準を自動適用。

### 開発者体験
認知負荷が軽減。開発者はビジネス価値に集中できる。

### 完全な監査証跡
すべてのユーザー入力・AI応答がタイムスタンプ付きで `aidlc-docs/audit.md` に記録される。

---

## 用語の整理

AI-DLCでは従来のアジャイル用語を一部刷新しています。

| 従来用語 | AI-DLC用語 | 説明 |
|---------|-----------|------|
| スプリント | **ボルト（Bolts）** | 時間・日単位の短い作業サイクル |
| エピック | **作業単位（Units of Work）** | システムを分解した開発単位 |
| バックログ | Backlog（継続） | スコープ外として保留した作業 |

## 生成されるドキュメント構造

AI-DLCはすべての成果物を `aidlc-docs/` ディレクトリに生成します。

```
aidlc-docs/
├── inception/
│   ├── plans/                  # 実行計画
│   ├── reverse-engineering/    # 既存コードの解析結果（brownfield）
│   ├── requirements/           # 要件定義書
│   ├── user-stories/           # ユーザーストーリー
│   └── application-design/     # アプリケーション設計
├── construction/
│   ├── plans/                  # 実行計画
│   ├── {unit-name}/
│   │   ├── functional-design/  # 機能設計
│   │   ├── nfr-requirements/   # 非機能要件
│   │   ├── nfr-design/         # 非機能設計
│   │   ├── infrastructure-design/ # インフラ設計
│   │   └── code/               # コード生成サマリー
│   └── build-and-test/         # ビルド・テスト指示
├── operations/                 # Operationsフェーズ（将来拡張）
├── aidlc-state.md              # 進捗状態追跡
└── audit.md                    # 完全な監査ログ
```

アプリケーションコードは **ワークスペースルートに直接** 生成されます（`aidlc-docs/` 内には入りません）。
