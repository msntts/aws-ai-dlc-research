## 概要

AI-DLC の拡張システムにより、セキュリティ・テスト・レジリエンシーなどの追加ルールをコアワークフローに重ねることができます。

拡張ルールは **ブロッキング制約** です。有効な拡張のルールに準拠しない限り、ステージの完了が許可されません。

---

## 仕組み

各拡張は同一ディレクトリ内の**2ファイル**で構成されます：

```
extensions/
└── security/
    └── baseline/
        ├── security-baseline.md          # 拡張ルール本体
        └── security-baseline.opt-in.md   # オプトインプロンプト
```

### ワークフロー起動時の処理

1. AI-DLC が `extensions/` ディレクトリを再帰的にスキャン
2. `*.opt-in.md` ファイル**のみ**を読み込む（ルール本体は読まない）
3. Requirements Analysis 時にオプトインプロンプトをユーザーに提示

### ユーザーのオプトイン/アウト

- **オプトイン** → 対応するルールファイルを読み込み、以降のすべてのステージで強制適用
- **オプトアウト** → ルールファイルは読み込まれない（コンテキスト節約）
- **`*.opt-in.md` がない拡張** → 常時強制適用（オプトアウト不可）

## 組み込み拡張

### Security Baseline（セキュリティベースライン）

**パス：** `extensions/security/baseline/`

セキュリティのベースラインルールを適用します。OWASP Top 10 や AWS セキュリティベストプラクティスに基づく設計・実装の検証が含まれます。

{: .important }
> セキュリティ拡張ルールは参照実装です。各組織は本番ワークフローへの適用前に、自組織のルールをカスタマイズしてテストしてください。

**推奨：** 本番グレードのアプリケーションでは有効にする。プロトタイプでは任意。

### Property-Based Testing（プロパティベーステスト）

**パス：** `extensions/testing/property-based/`

プロパティベーステストのルールを適用します。Hypothesis（Python）や fast-check（TypeScript）などのフレームワークを使ったテスト生成を強制します。

### Resiliency Baseline（レジリエンシーベースライン）

**パス：** `extensions/resiliency/baseline/`

レジリエントなワークロードのベストプラクティスを適用します。サーキットブレーカー、リトライ戦略、グレースフルデグラデーションなどのパターンを含みます。

{: .important }
> レジリエンシー拡張ルールも参照実装です。各組織でカスタマイズして使用してください。

## カスタム拡張の追加

組織固有のルール（API設計標準、コンプライアンス要件など）を追加できます。

### 手順

**1. ディレクトリを作成**

```
extensions/
└── compliance/          # 新しいカテゴリ
    └── gdpr/            # 拡張名
        ├── gdpr.md                # ルールファイル
        └── gdpr.opt-in.md         # オプトインプロンプト
```

**2. ルールファイルを作成（`gdpr.md`）**

```markdown
## Rule GDPR-01: 個人データの識別

### Rule
個人データを含むすべてのフィールドを識別し、適切な暗号化と
アクセス制御を設計に含めること。

### Verification
- [ ] 個人データフィールドがすべて識別されている
- [ ] 保存時の暗号化が設計に含まれている
- [ ] アクセス制御が設計に含まれている
```

**ルール命名規則：** `## Rule <PREFIX-NN>: <タイトル>` の形式。PREFIX は一意のカテゴリ識別子（例：`GDPR-01`）。監査ログや準拠サマリーで参照されるため、すべての拡張で一意である必要があります。

**3. オプトインファイルを作成（`gdpr.opt-in.md`）**

```markdown
## GDPR コンプライアンスルールを有効にしますか？

A) はい — GDPR コンプライアンスルールをすべてのステージで強制適用する
B) いいえ — GDPR ルールを適用しない

[Answer]:
```

`*.opt-in.md` を省略すると、その拡張は常時強制適用になります。

## 企業標準の組み込み方

組織全体で使う標準（API設計ガイドライン、セキュリティポリシーなど）は、拡張として一度定義するだけで、すべてのプロジェクトに自動適用されます。

```
.aidlc-rule-details/
└── extensions/
    ├── security/baseline/      # AWS提供（カスタマイズ推奨）
    ├── testing/property-based/ # AWS提供（カスタマイズ推奨）
    ├── resiliency/baseline/    # AWS提供（カスタマイズ推奨）
    └── my-org/                 # 組織固有の拡張
        ├── api-standards/
        │   ├── api-standards.md
        │   └── api-standards.opt-in.md
        └── compliance/
            └── gdpr.md         # opt-in なし → 常時強制
```

## 準拠サマリーの形式

拡張が有効な場合、各ステージの完了時に準拠サマリーが表示されます：

```
## 拡張ルール準拠サマリー

| ルール | 状態 | 備考 |
|--------|------|------|
| SEC-01: 入力検証 | ✅ 準拠 | すべての入力にバリデーション実装 |
| SEC-02: 認証必須 | ✅ 準拠 | JWT認証を設計に含む |
| SEC-03: 暗号化 | ❌ 非準拠 | 保存時の暗号化が未設計 |
| GDPR-01: 個人データ識別 | N/A | 個人データなし |
```

非準拠の場合はブロッキング判定となり、解決するまでステージを完了できません。
